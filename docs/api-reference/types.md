# Type Definitions Reference

This document describes all TypeScript and Python type definitions used in Kanban AI.

## Overview

Types are shared between:
- **Frontend**: TypeScript types in `apps/desktop/src/types/`
- **Backend**: Rust structs in `apps/desktop/src-tauri/`
- **Agent**: Pydantic models in `services/agent/src/api/models.py`

---

## Core Types

### Priority

Ticket priority levels.

=== "TypeScript"
    ```typescript
    type Priority = 'low' | 'medium' | 'high' | 'critical';
    ```

=== "Python"
    ```python
    from typing import Literal
    Priority = Literal["low", "medium", "high", "critical"]
    ```

=== "Rust"
    ```rust
    #[derive(Debug, Serialize, Deserialize)]
    #[serde(rename_all = "lowercase")]
    pub enum Priority {
        Low,
        Medium,
        High,
        Critical,
    }
    ```

### Effort

Effort estimation using t-shirt sizes.

=== "TypeScript"
    ```typescript
    type Effort = 'xs' | 's' | 'm' | 'l' | 'xl';
    ```

=== "Python"
    ```python
    Effort = Literal["xs", "s", "m", "l", "xl"]
    ```

| Size | Typical Duration |
|------|-----------------|
| `xs` | < 1 hour |
| `s` | 1-4 hours |
| `m` | 1-2 days |
| `l` | 3-5 days |
| `xl` | 1+ weeks |

## Entity Types

### Ticket

The main entity representing a work item.

```typescript
interface Ticket {
  id: string;           // UUID
  title: string;        // Max 500 chars
  description?: string; // Markdown supported
  priority?: Priority;
  effort?: Effort;
  columnId: string;     // Foreign key to Column
  position: number;     // Order within column
  labels: Label[];
  dueDate?: string;     // ISO 8601 date string
  comments: Comment[];
  createdAt: string;    // ISO 8601 datetime
  updatedAt: string;    // ISO 8601 datetime
}
```

## Best Practices

### Type Safety

1. **Always use defined types** - Avoid `any` or `unknown` when types exist
2. **Import from central location** - Use `import { Ticket } from '@/types'`
3. **Validate at boundaries** - Use Pydantic/Zod for API validation

### Type Conversions

When converting between frontend and backend:

```typescript
// Frontend camelCase to Backend snake_case
function toSnakeCase(ticket: Ticket): BackendTicket {
  return {
    id: ticket.id,
    title: ticket.title,
    column_id: ticket.columnId,  // Note: camelCase -> snake_case
    due_date: ticket.dueDate,
    created_at: ticket.createdAt,
    updated_at: ticket.updatedAt,
  };
}
```

### Optional Fields

- Use `?` for truly optional fields
- Use `| null` when explicitly setting to null is meaningful
- Use default values in Python models

```typescript
// Optional - may not exist
dueDate?: string;

// Nullable - exists but can be cleared
dueDate: string | null;
```
